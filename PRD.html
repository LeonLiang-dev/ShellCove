ShellCove
macOS 原生服务器管理与连接工具

把「这台服务器是干什么的」和「我要马上连上去」放进同一个窗口。轻量、原生、纯本地， 用一条清晰的左栏列表和一块可被终端接管的右侧详情区完成全部核心工作。

01背景与问题

需要管理多台服务器的人，通常同时维护着四份互相不同步的「服务器真相」： ~/.ssh/config 里的连接参数、密码管理器里的密码、备忘录或聊天记录里的用途说明、 以及自己脑子里的「哪台是生产、哪台能重启」。

这个断裂带来三个具体后果：

  • 连接成本高。每次连一台不常用的机器，都要先翻记录确认 IP、端口、用户和跳板机。
  • 误操作风险。生产与测试机器在终端里长得完全一样，缺少视觉与操作上的隔离提示。
  • 知识流失。「这台机器跑什么、能不能重启、出问题找谁」只存在于个人记忆里，换人或隔几个月就失效。

现有方案各有取舍：终端型工具（iTerm2、Warp）擅长连接但不管理资料；笔记型工具（Notion、Obsidian）擅长记录但不能连接； 面板型工具（Termius、SecureCRT）功能完整但偏重，且多为订阅制、跨平台妥协。

产品判断。目标用户不需要又一个全能终端，而需要一个「服务器通讯录 + 一键连接」。 因此 ShellCove 不做终端替代品，只做一台服务器从「被记住」到「被连上」之间最短的那条路径。

02产品定位与目标

2.1 一句话定位

一款 macOS 原生、体积轻、启动快的服务器资料库：左边选机器，右边看它是什么，点一下就在原地连上去。

2.2 设计原则

原则含义可观察的判定
轻 不引入 Web 运行时；除终端组件外不引入第三方运行时依赖；不做常驻后台进程。 安装包 < 12 MB；冷启动 < 1 s；空闲内存 < 120 MB。
原生 使用系统控件、系统快捷键、系统外观与系统材质，跟随深浅色与强调色。 所有交互可用键盘完成；系统切换深色时无残留亮色块。
本地优先 数据默认只存在本机；不登录、不联网、不上传；连接只由用户主动发起。 断网时可正常增删改查；除 SSH 外无任何出站请求。
一屏完成 连接不弹新窗口、不跳转页面，终端在原位接管右栏。 从选中服务器到出现 shell 提示符，不需要切换窗口。

2.3 成功判据（定性）

首版上线后，用户能在不查阅任何外部记录的情况下完成三件事： 新增一台服务器并写清用途、在 5 秒内找到并连上任意一台已知服务器、在连接前就能判断这台机器是否属于生产环境。 量化指标 TBD（个人项目，暂无埋点计划）。

03范围与优先级

P0 首版必须有，缺失则核心闭环不成立 P1 首版之后补充，不影响主流程

3.1 P0：最小完整闭环

能力包含闭环中的位置
服务器资料管理新增、编辑、删除；名称、主机、端口、用户、环境、分组、标签、用途说明（Markdown）、负责人、到期时间、系统把「服务器是什么」沉淀下来
组织与查找左栏上下结构：分组在上、列表在下；标签筛选；⌘K 全局搜索在 50 台以内快速定位
详情查看右侧展开状态、用途说明、基础信息、最近连接连接前确认这台机器是什么
连接内置终端，覆盖右侧整个面板；支持 SSH Key / ssh-agent 与密码认证（密码存 Keychain）；复用 ~/.ssh/config从「知道」到「连上」
连接记录开始时间、时长、退出码；异常结束标记事后回溯「我什么时候动过它」
本地存储本机数据库；无账号体系不引入服务端依赖

3.2 P1：首版后补充

  • 连通性探活与时延采样（手动触发，不做轮询）。
  • 从 ~/.ssh/config 批量导入 Host 条目。
  • JSON 备份导出与恢复（不含任何密钥）。
  • 菜单栏快捷入口：最近连接的前 5 台。
  • 多终端标签页。

3.3 明确不做（首个大版本内）

不做原因
私钥托管只记录私钥路径，不复制、不托管密钥文件内容；密码则存储于系统 Keychain。
iCloud / 多设备同步引入同步即引入账号、冲突合并与泄露面，与「纯本地」定位冲突。
团队协作与权限目标用户是个人；团队场景需要服务端，属于另一个产品。
SFTP / 文件传输不是「找到并连上」闭环的一部分，会显著拉高终端层复杂度。
资源监控与告警需要常驻采集，违背轻量与省电原则。
非 macOS 客户端原生体验是本产品的核心卖点，跨平台会稀释它。

04用户与场景

4.1 目标用户

主要用户
个人开发者 / 独立开发者，手上有 5–50 台服务器
次要用户
3–10 人小团队的运维或后端负责人，需要把机器用途讲清楚
使用频次
每天 1–10 次连接，多为重复访问少数几台机器
技术水平
熟悉 SSH，但不愿为每台机器维护一份笔记或脚本
现有替代
备忘录 + ~/.ssh/config + 终端历史 + 脑子里记

4.2 典型场景

场景 A：凌晨的故障定位

收到告警，需要连上生产 API 机器看日志。用户打开 ShellCove，左侧列表第一屏就能看到带红色「生产」标记的 api-prod-01，右侧用途说明里直接写着「重启前先摘流量，日志在 /var/log/svc/api.log」。 点「连接」，终端在右栏展开，不需要回忆任何参数。完成判据：出现 shell 提示符，且用户没有输入过 IP。

场景 B：接手一台不熟悉的机器

同事说「你去看下 redis-cache-01」。用户 ⌘K 输入 redis，回车打开详情：状态显示告警、时延偏高、 用途说明写着「内存使用率 82%，扩容评审中」。用户在连接之前就知道这台机器不能随手重启。 完成判据：用户在连接前读到了至少一条风险说明。

场景 C：整理积攒下来的机器

用户一口气新增 8 台机器，按生产、测试、开发分组，写清用途与到期时间，给关键机器打上「数据库」「跳板机」标签。 此后每次连接都从这份清单出发，不再依赖记忆。完成判据：清单中每台机器都有环境与用途说明。

05信息架构

5.1 窗口结构

单窗口，两列。左列固定宽度，内部上下分区；右列是可被终端整体接管的详情面板。 这个结构直接来自已确认的视觉原型。

5.2 对象模型

对象职责关系
服务器 Server一台可连接的主机，是所有资料与记录的归属对象属于 1 个分组；拥有 0..n 个标签；拥有 0..n 条连接记录
分组 Group按环境或用途对服务器做一级归类，左栏上半部分展示包含 0..n 台服务器；服务器只能属于 1 个分组
标签 Tag跨分组的横向标记，如「数据库」「跳板机」与服务器多对多；不做层级
连接记录 Session Record一次终端会话的事实记录属于 1 台服务器；只读，不可编辑
应用设置 Settings外观、默认终端行为、探活开关等全局唯一
一个刻意的取舍。 分组是「唯一归属」，标签是「多重标记」。服务器不能同时属于生产与测试——环境必须唯一， 否则连接前的风险提示就失去意义。需要横向归类时用标签。

06功能需求

以下模块按用户任务组织。每个模块定义目的、布局、触发、处理规则、结果与状态变化、异常； 跨模块共用的字段、校验与连接规则统一放在第 7 章，不在此处重复。

FR-01

服务器列表与分组

P0

目的

让用户在 50 台以内一眼看到目标机器，并始终清楚它属于哪类环境。

布局

左列固定宽度，上下两个区域，中间以一条分隔线区分：

  • 上半区（分组）：分组列表，每行显示环境色点、名称、服务器数量；下方是标签胶囊行，可横向换行。
  • 下半区（列表）：标题行（当前分组名 + 数量 + 新增按钮）、筛选胶囊（全部 / 在线 / 最近连接）、可滚动的服务器行。
  • 底部：一行存储状态说明，不承载操作。

服务器行内容

元素规则
状态点在线为绿色（呼吸动画仅在详情打开时启用）；告警为琥珀色；离线或未知为灰色。未知状态不显示为绿色。
名称单行截断，尾部省略；显示用户录入的显示名，不强制等于主机名。
主机等宽字体，显示 host；端口不是 22 时显示 host:port。
环境标记小尺寸色块文字（生产 / 测试 / 开发 / 基础设施），颜色与分组色点一致。
最近连接右对齐的弱化文字：2 小时前 / 昨天 / 12 天前 / 从未。

触发与行为

  • 点击任一行 → 选中该服务器，右侧切换为详情；若终端正在占据右栏，则先结束当前会话并返回详情。
  • 点击分组 → 列表按该分组过滤，标题与数量同步更新；当前选中服务器若不属于该分组，右侧保持原样但列表不再高亮它，直到用户重新选择。
  • 点击标签 → 分组高亮清除，列表按标签过滤；再次点击同一标签 → 取消过滤，回到「全部服务器」。
  • 分组与标签互斥：同一时刻只有一个过滤条件生效。
  • 没有服务器或筛选结果为空 → 显示空状态：一句说明 + 「新增服务器」按钮；若因筛选为空，额外显示「清除筛选」。

结果与状态变化

选中的服务器在列表中以「左侧 3px 环境色条 + 浅底色」标记；选中状态在同一窗口内唯一。

异常

  • 分组被删除时，其下服务器迁移到默认分组「未分组」，不级联删除。
  • 服务器数量超过 200 台时，列表需保持可滚动且不卡顿；若出现掉帧，启用分页渲染。
FR-02

搜索与筛选

P0

目的

在不想翻列表的时候，用键盘直接跳到目标机器。

触发

  • 点击标题栏搜索框，或按 ⌘K，打开居中搜索面板。
  • 按 Esc 或点击遮罩关闭。

处理规则

规则定义
匹配字段名称、主机地址、域名、登录用户、负责人、地域、标签。默认不匹配用途说明正文，避免噪音。
匹配方式不区分大小写的包含匹配；名称为前缀命中时排在包含命中之前。
结果数量最多显示 8 条，超出部分不滚动加载，改为提示「继续输入以缩小范围」。
空输入显示最近连接的 5 台服务器；没有任何记录时显示全部服务器的前 5 台。
键盘↑ ↓ 移动高亮，↵ 打开所选服务器，Esc 关闭。

结果与状态变化

按 ↵ 后：关闭搜索面板 → 清除分组与标签过滤 → 列表滚动到该服务器并选中 → 右侧加载详情 → 焦点回到服务器列表。该操作不自动发起连接。

异常

无匹配结果时显示「未找到匹配的服务器」，并提示可搜索的字段；不显示空白面板。

FR-03

服务器详情

P0

目的

在连接之前回答三个问题：它是什么、它现在什么状态、连上去该注意什么。

布局（自上而下）

  1. 头部：环境标记、上次连接时间、服务器名称、状态点、user@host、端口、系统版本；右侧为「连接」「复制」「更多」三个操作。
  2. 状态条：状态、延时、认证方式、负责人，右侧为延时走势小图。
  3. 作用与说明卡片：Markdown 渲染的用途、风险与操作约定，右上角「编辑」。
  4. 基础信息卡片：主机、域名、端口/用户、地域、分组、系统、到期时间、最近连接，以及标签行。
  5. 最近连接卡片：最近 4 条记录，含时间、时长、退出码；右上角「全部记录」。

处理规则

  • 「作用与说明」是该页面的主内容，字号与行高高于其他卡片，必须位于基础信息之前。
  • 说明为空时，卡片显示引导语「写清楚这台机器的作用、能不能重启、日志在哪」与「添加说明」按钮，而不是隐藏卡片。
  • 点击主机地址或用户名 → 复制纯文本并弹出轻提示，不打开外部程序。
  • 点击「复制」→ 复制完整 ssh 命令（见 7.3），并提示「已复制 ssh 命令」。
  • 点击「连接」→ 进入 FR-05，终端覆盖整个右侧面板。
  • 状态与延时为「未知」时，显示灰色与「未检测」，不显示 0 ms，也不做失败推断。

异常

  • 服务器在详情打开期间被删除（例如通过搜索面板之外的入口）→ 右栏切换为空状态，不保留幽灵数据。
  • 说明中的 Markdown 含不支持的语法 → 按纯文本降级显示，不报错、不阻断渲染。
FR-04

新增与编辑服务器

P0

触发

  • 列表标题行「+」按钮、⌘N、空状态按钮 → 打开新增表单。
  • 详情中的「编辑」或 ⌘E → 打开编辑表单，预填当前值。

布局

以窗口内居中的表单面板呈现，而非新窗口。分为「连接」「资料」两组字段，底部为「取消 / 保存」。 新增时保存按钮在必填项完整前禁用。

字段与校验

字段定义见 7.1。必填项为：名称、主机、登录用户、环境。其余可留空，留空时的展示规则见 7.1。

处理规则

  • 保存时对主机与名称去除首尾空格；主机不允许包含空格、@、协议前缀。
  • 端口默认 22，仅接受 1–65535 的整数。
  • 名称重复时提示「已存在同名服务器」，但允许用户以「仍然保存」继续（同名可能出现在不同分组）。
  • 私钥路径为空时，连接交给系统 ssh-agent 与 ~/.ssh/config；填了路径则作为 -i 参数，且不复制密钥文件。
  • 编辑保存后立即刷新左栏与右栏；不重置当前选中项。
  • 取消或按 Esc 时若有未保存改动，二次确认「放弃修改」。

结果与状态变化

新增成功后：列表插入到当前分组末尾并选中该服务器，右栏显示详情，焦点在「连接」按钮上。 编辑成功后：仅刷新受影响字段，不改变列表排序。

异常与边界

  • 主机不可达不影响保存——保存资料与验证连通是两件事。
  • 私钥路径指向不存在的文件：保存时仅警告，不阻断；连接失败时再给出明确错误。
  • 删除服务器需二次确认，文案包含服务器名称与「该服务器的连接记录将一并删除」。
FR-05

连接与终端

P0

目的

从「看见这台机器」到「拿到 shell」之间只隔一次点击，并且不离开当前窗口。

触发

  • 详情头部「连接」按钮，或 ⌘⏎。
  • 终端已打开时，再次点击左侧其他服务器不会复用当前终端，而是结束会话并回到详情（避免误连）。

布局

终端从下方轻微上浮并覆盖整个右侧面板，左栏保持不变：

  • 终端头部：左起「‹ 详情」返回按钮、当前服务器标签（含状态点）、右侧延时信息与「断开」按钮。
  • 终端主体：占满剩余高度，等宽字体，深色背景（不跟随浅色外观）。
  • 终端底部状态栏：连接状态、user@host、shell 类型、窗口字符尺寸。

处理规则

  • 连接命令固定为 ssh -p {port} {user}@{host}，追加 -i {privateKeyPath}（若有）；其余选项交给系统 SSH 配置。
  • 不自动接受未知主机指纹：首次连接的主机密钥确认提示原样显示在终端内，由用户决定。
  • 连接中显示「正在连接…」，收到第一段输出后切换为「已连接」。
  • 点击「详情」或按 Esc：结束当前会话（发送终止信号），切回详情，并写入连接记录。
  • 关闭窗口或退出应用：终止所有活动会话，记录标记为「中断」。
  • 窗口尺寸变化时，终端字符网格同步调整并通知远端。

结果与状态变化

连接成功时：服务器 lastConnectedAt 更新，左栏「最近连接」文本刷新，同时创建一条进行中的连接记录。 会话结束时记录补齐时长与退出码。

异常

情况表现
DNS 解析失败 / 主机不可达终端内显示 ssh 原始错误，头部状态变为「连接失败」，底部状态栏显示退出码；提供「重试」按钮。
权限被拒绝原样显示 ssh 的 Permission denied；Key 认证时附加提示「请确认 ssh-agent 已加载对应密钥，或填写私钥路径」，密码认证时提示「请检查已保存的密码」。
主机指纹变更不自动覆盖；显示 ssh 原始警告，并提示用户核对后再手动处理。
空闲超时 / 网络中断会话自然退出，记录退出码；不自动重连，避免对生产环境产生意外操作。
FR-06

连接记录

P0

目的

回答「我最近有没有动过这台机器」，并为故障回溯提供最小事实。

规则

  • 每条记录包含：开始时间、结束时间、时长、退出码、结束方式（正常退出 / 用户断开 / 应用退出 / 异常）。
  • 记录在会话开始时创建，结束时补齐；不记录任何终端输入输出内容。
  • 记录只读，用户不能手动新增或编辑，只能随服务器一起删除。
  • 详情页展示最近 4 条；「全部记录」打开该服务器的完整列表。
  • 启动时若发现未结束的记录（上次崩溃或强退），标记为「异常结束」，时长按「未知」显示，不以现在时间计算。
  • 单台服务器保留最近 200 条记录，超出后按时间淘汰最旧记录。

展示

每行：终端图标、开始时间（今天/昨天/日期）、时长（等宽）、退出码（成功为绿色，非 0 为红色）。

FR-07

设置与外观

P1

范围

  • 外观：跟随系统 / 深色 / 浅色。
  • 终端：字体大小（11–16）、光标样式、是否启用响铃。
  • 连接：连接超时秒数、是否在打开详情时自动探活（默认关闭）。
  • 数据：显示数据库文件位置、导出备份入口。

首版仅实现「跟随系统 / 深色 / 浅色」与终端字号，其余随 P1 补充。

FR-08

备份导入导出

P1

规则

  • 导出为单个 JSON 文件，包含服务器、分组、标签与连接记录；不包含任何密码、私钥内容或 Keychain 条目。
  • 文件带版本号；导入时若版本高于当前应用支持版本，拒绝导入并说明原因。
  • 导入遇到同名服务器：默认跳过并汇总数量，可展开选择「覆盖 / 保留两份」。
  • 导入为先写入临时集合、全部校验通过后再落库；中途失败则不产生部分数据。
FR-09

SSH 配置导入

P1

规则

  • 读取 ~/.ssh/config，解析不含通配符、不含 Include 递归的 Host 块。
  • 导入字段：Host 别名 → 名称，HostName → 主机，User → 用户，Port → 端口，IdentityFile → 私钥路径。
  • 已存在的服务器按「主机 + 端口 + 用户」判定重复，默认跳过；导入完成后显示「新增 n 台，跳过 m 台」。
  • 只读解析，绝不改写用户的 SSH 配置文件。
  • 文件不存在或无有效 Host 时，给出说明而不是空列表。

7.3 连接命令构造

# 基础形式
ssh -p {port} {user}@{host}

# 指定私钥时追加（路径原样传入，不复制、不转义用户目录）
ssh -p {port} -i {privateKeyPath} {user}@{host}

# 终端模式需强制分配 tty，并声明 256 色
TERM=xterm-256color ssh -tt -p {port} {user}@{host}
  • 不注入 StrictHostKeyChecking=no，不静默接受主机密钥。
  • ProxyJump、ProxyCommand 等选项由 ~/.ssh/config 决定，应用不覆盖。
  • 「复制命令」复制的是基础形式，不包含 TERM 与 -tt。
  • 密码认证在 M3 通过 SSH_ASKPASS 助手从 Keychain 读取密码，密码不进入命令行参数，也不写入环境变量。

7.4 状态定义

状态含义进入条件
连通未知从未检测或超过 24 小时未检测新增服务器后；应用启动且无历史检测
在线最近一次 TCP 探测在 2 秒内完成手动刷新或（开启时）打开详情触发
告警能连通但时延高于该服务器历史中位数 2 倍，或上次连接异常退出探活结果满足条件
离线最近一次探测超时或被拒绝探测失败

首版不主动轮询。状态仅作为提示，不能作为「机器一定可用」的承诺；文案使用「最近检测」而非「当前状态」。

7.5 删除与数据保留

  • 删除服务器 → 二次确认 → 服务器与其连接记录一并删除；分组与标签保留。
  • 删除分组 → 组内服务器迁移到「未分组」，不删除服务器；需二次确认并显示将影响的服务器数量。
  • 删除标签 → 仅解除关联，不删除服务器。
  • 首版不提供回收站；删除不可撤销，因此确认弹窗必须包含对象名称。

7.6 隐私与安全

  • 本地数据库中不存储密码、私钥内容、会话内容；密码认证的凭据存放在系统 Keychain，按服务器 ID 索引。
  • 不采集遥测、不联网检查更新（首版）。
  • 除用户主动发起的 SSH 连接与可选的 TCP 探活外，应用不产生其他网络请求。
  • 导出文件不包含任何凭据；导出前明确提示这一点。

9.3 关键实现决策：为什么不做沙盒

App Sandbox 禁止应用执行任意系统可执行文件。终端方案需要拉起 /usr/bin/ssh， 在沙盒下无法复用用户已有的 ~/.ssh/config、ssh-agent 与 ProxyJump，产品最核心的「零配置连接」会失效。

方案优点代价结论
非沙盒 + 系统 ssh完全复用用户环境；实现简单；行为与终端一致不能上 Mac App Store；必须 Developer ID 签名并公证采用
沙盒 + SwiftNIO SSH可上架 App Store需自行实现 agent 转发、config 解析、known_hosts；行为与系统 ssh 存在差异不做
沙盒 + 内置 ssh 二进制可上架需自带 OpenSSH 构建与许可证处理，体积与维护成本高不做
分发方式随之确定。 首版通过 Developer ID 签名的独立安装包分发（本地使用可直接 Xcode 运行）。若后续必须上架 App Store， 需要切换到 SwiftNIO SSH 方案，属于产品级改造成本，见待定问题 Q1。

9.5 终端接入要点

  1. forkpty 创建主/从伪终端，子进程 execv 系统 ssh；父进程保留 master fd。
  2. master fd 设为非阻塞，用 DispatchSource.makeReadSource 读取，数据送入 SwiftTerm 的 feed。
  3. 实现 SwiftTerm 代理的 send，把用户按键写回 master fd；不可打印输入由终端组件处理。
  4. 窗口尺寸变化时用 TIOCSWINSZ 更新从端尺寸，再由 SSH 通道通知远端。
  5. 会话结束用 waitpid 取退出码；读取剩余输出后再关闭 fd，避免丢最后几行。
  6. 应用退出前向所有子进程发送 SIGHUP，并等待回收，避免僵尸进程。
  7. 密码认证时设置 SSH_ASKPASS_REQUIRE=force 并指向应用内的 askpass 助手，由助手按服务器 ID 从 Keychain 取密码返回给 ssh；密码不落盘、不入环境变量。

AC-02必填校验缺少主机或用户时保存按钮禁用；端口输入 70000 时提示范围错误且无法保存。
AC-03分组过滤点击「生产环境」后，列表只显示生产机器，标题与数量同步；点击「全部服务器」恢复。
AC-04标签过滤点击「# 数据库」后列表只剩带该标签的机器；再次点击取消过滤。
AC-05搜索定位⌘K 输入主机片段，回车后列表滚动到该机器、右栏显示其详情，且没有发起连接。
AC-06详情主次「作用与说明」在基础信息之前；说明为空时出现引导语与添加按钮，而非空白卡片。
AC-07复制命令点击「复制」后剪贴板内容等于 ssh -p 22 user@host，并出现轻提示。
AC-08连接覆盖点击「连接」后终端占满右栏（不是底部抽屉），左栏不变；出现 shell 提示符后可正常输入命令。
AC-09返回详情按 Esc 或点「详情」回到详情页，会话结束；最近连接卡片新增一条带时长的记录。
AC-10连接失败把主机改为不可达地址后连接，终端显示 ssh 错误，头部状态为「连接失败」，提供「重试」，应用不崩溃。
AC-11切换服务器终端打开时点击另一台服务器，当前会话结束并回到详情，不出现两个终端叠加。
AC-12删除确认删除服务器需二次确认，文案含名称与「连接记录将一并删除」；确认后列表与搜索中均不再出现。
AC-13空状态清空所有数据后首次启动，右栏显示引导页与两个入口，不显示错误或空白。
AC-14外观切换系统切换深色/浅色时，窗口、列表、详情无残留色块；终端始终保持深色背景。
AC-15中文输入在终端中输入中文命令或注释，字符宽度正确、无乱码、候选框位置正常。
AC-16窗口缩放拖动改变窗口大小，终端内容自动重排，远端 stty size 输出与实际网格一致。
AC-17异常退出恢复终端连接时强制退出应用，再次启动后该记录显示「异常结束」，时长未知，不出现负值或超长时长。
AC-18备份往返导出 JSON 后清空数据再导入，服务器、分组、标签、记录数量与内容一致；文件中不含密钥内容。
AC-19密码认证新增服务器时选择「密码」并填写密码后保存；重新打开编辑表单显示密码已保存；数据库中查不到明文密码；删除服务器后 Keychain 条目一并清除。

12风险与对策

编号风险影响对策
R1非沙盒分发带来的信任成本高Developer ID 签名 + notarization；发布页说明为何需要执行系统 ssh；首版优先本地自用与开发者分发。
R2PTY 与 SSH 的信号/退出码处理不完整中M3 优先做会话生命周期测试：正常退出、Ctrl+D、远端断开、强退四种路径都写记录；waitpid 与 fd 关闭顺序单独验证。
R3CJK 宽字符与输入法在终端中的渲染问题中M3 阶段用中文目录名、中文注释、emoji 三类输入做专项验收（AC-15）；必要时调整 SwiftTerm 字体与列宽计算。
R4SwiftData 模型演进导致数据丢失高从 M1 起使用 VersionedSchema；每次改字段都补迁移计划与一条迁移测试。
R5私钥路径失效或被移动低不复制密钥；连接失败时解析 ssh stderr，识别 no such identity 并引导重新选择路径。
R6首次连接的主机指纹确认被终端组件吞掉中不添加 StrictHostKeyChecking=no；M3 用一台全新主机验证指纹提示可交互。
R7浅色外观下玻璃材质对比度不足低M5 对两套外观逐屏检查；正文使用不透明度 0.62 以上的文字色；关键信息不依赖材质透出。
R8列表规模增长后的滚动性能低目标场景 50 台以内；用 500 条模拟数据做压力测试，超阈值再引入分页。
R9功能蔓延导致「轻量」定位失守中第 3.3 节的「不做清单」作为范围边界；任何新增能力必须先回答它是否服务于「找到并连上」。
